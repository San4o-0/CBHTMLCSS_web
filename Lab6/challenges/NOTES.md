## Challenge 1. Flexbox: responsive header — `01-header.html`

**Ідея простими словами:** header — це «полиця» (flex), на якій стоять logo, меню і кнопка.
Меню каже: «Я хочу приблизно 20rem місця». Якщо в рядку стільки немає, меню саме переїжджає на
новий рядок.

| Що зроблено                           | Навіщо                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------- |
| `display: flex; align-items: center`  | Усе в один рядок, по центру по висоті                                     |
| `gap: 12px 24px`                      | Відстань між елементами без margin-ів                                     |
| `flex-wrap: wrap` на header           | Дозволяє переносити елементи                                              |
| `.navigation { flex: 1 1 20rem }`     | «Бажана» ширина меню 20rem; не влазить — новий рядок. **Без media query** |
| `flex-wrap: wrap` на `.navigation`    | Посилання меню теж переносяться між собою                                 |
| `margin-inline-start: auto` на кнопці | Притискає кнопку до правого краю                                          |

Поведінка (перевірено скриншотами): широко (1100px) — усе в рядку; середньо (540px) — logo +
меню / кнопка праворуч; вузько (360px) — logo / меню / кнопка. Порядок переносу задає DOM: flex
кладе елементи по черзі, і першим «не влазить» останній — кнопка. Другий приклад на сторінці — той самий header у контейнері 26rem: перенос
відбувається без зміни вікна, бо flex реагує на місце, а не на viewport.

## Challenge 2. Grid: adaptive cards — `02-cards.html`

```css
grid-template-columns: repeat(auto-fit, minmax(min(220px, 100%), 1fr));
```

**Простими словами:** «Зроби стільки колонок, скільки влізе, кожна не вужча за 220px».

- `min(220px, 100%)` — захист: якщо контейнер вужчий за 220px, колонка = 100% контейнера і не
  вилазить. Без цього на дуже вузькому екрані був би overflow.
- На 360px — 1 колонка (виміряно), далі 2, 3, 4 — без жодної media query.

### Експеримент auto-fit vs auto-fill

З 6 картками різниці **не видно**: вони заповнюють усі колонки. Тому на сторінці є приклад з 2
картками:

|             | Що відбувається на широкому екрані                                      |
| ----------- | ----------------------------------------------------------------------- |
| `auto-fit`  | Порожні колонки **схлопуються** → 2 картки розтягуються на всю ширину   |
| `auto-fill` | Порожні колонки **лишаються** → 2 картки вузькі, праворуч порожнє місце |

Коли що брати: `auto-fit` — щоб картки заповнювали ряд; `auto-fill` — щоб картка завжди мала
однакову ширину незалежно від кількості.

## Challenge 3. Page layout: Grid + Flexbox — `03-page-layout.html`

**Grid** — для каркаса (header, sidebar, main, footer) через `grid-template-areas`.
**Flexbox** — для header, навігації, груп кнопок, footer.

- Мобільний порядок Header → Main → Sidebar → Footer збігається з порядком у DOM: main іде
  раніше за sidebar і для screen reader-ів.
- **Один breakpoint `48rem`** — він змінює **структуру** (sidebar переїжджає ліворуч). Таке не
  виразиш «гнучкою» властивістю, тому media query тут виправдана (висновок із дослідження 4.2).
- 48rem обрано, бо з цієї ширини sidebar отримує ≥ 12rem і не стискає main.
- `rem` у media query, а не `px` — breakpoint зсувається, якщо користувач збільшив шрифт.
- Сітка карток у main — `auto-fit + minmax()`, без своїх breakpoint-ів.
- Немає: float, таблиць, absolute, фіксованої ширини сторінки (`max-inline-size: 75rem`
  — це обмеження, а не фіксована ширина).

## Challenge 4. Subgrid: aligned cards — `04-subgrid.html`

|           | Без subgrid (`auto 1fr auto`)   | Subgrid (`span 3` + `subgrid`) |
| --------- | ------------------------------- | ------------------------------ |
| Read more | вирівняні внизу                 | вирівняні внизу                |
| Заголовки | різної висоти                   | рядок однакової висоти         |
| Текст     | починається на різній висоті ❌ | починається на одній лінії ✅  |

**Відповідь на питання §4.5 (на основі цього challenge):** у nested grid кожна картка рахує свої
рядки сама і не знає про сусідів — тому заголовок з 1 рядка і заголовок з 3 рядків дають різну
висоту першого рядка. Subgrid бере рядки **батьківської** сітки, а висота рядка батька —
максимум серед усіх карток у ряду. Без subgrid довелося б ставити `min-height` заголовку, який
ламається при іншому тексті, перекладі або збільшенні шрифту.

## Challenge 5. Container Query: reusable card — `05-container-card.html`

```css
.card-wrapper {
  container: card / inline-size;
} /* іменований контейнер */
@container card (width > 500px) {
  .product-card {
    grid-template-columns: auto 1fr;
  }
}
```

- `container: card / inline-size` — скорочення для `container-name: card` +
  `container-type: inline-size`.
- `container-type` — на **обгортці**, бо `@container` змінює стилі **нащадків** контейнера, а не
  його самого.
- Ім'я `card` потрібне, щоб запит дивився саме на цю обгортку, навіть якщо вище є інші
  контейнери.

**Експеримент (sidebar, main, modal):** на широкому екрані картка в sidebar вертикальна, у main і
modal — горизонтальна. На телефоні всі три вертикальні. CSS картки однаковий, `@media` у ньому
немає.

Сам layout `.content-layout` теж без media query: `flex-wrap` + `flex: 1 1 16rem` / `3 1 24rem`.

## Challenge 6. Container Query units — `06-cq-units.html`

| Одиниця           | 1 одиниця =                                                            |
| ----------------- | ---------------------------------------------------------------------- |
| `vw`              | 1% ширини **вікна**                                                    |
| `cqw`             | 1% ширини **контейнера**                                               |
| `cqi`             | 1% inline-розміру контейнера (у горизонтальному тексті = `cqw`)        |
| `cqb`             | 1% block-розміру (висоти) контейнера — потрібен `container-type: size` |
| `cqmin` / `cqmax` | менше / більше з `cqi` і `cqb`                                         |

Нюанс: з `container-type: inline-size` висота контейнера невідома, тому `cqb` (і отже `cqmin` /
`cqmax`) береться від висоти **viewport**. Для ширини компонента найпередбачуваніше `cqi`.

**Чому vw і cqi поводяться по-різному:** у прикладі A (vw) заголовки в широкій і вузькій картках
**однакові** — vw не знає, де лежить картка. У прикладі B (cqi) у вузькій картці заголовок
менший. У прикладі C можна тягнути рамку: cqi-заголовок змінюється, vw-заголовок стоїть на
місці. Під кожним заголовком сторінка показує його computed `font-size`.

Виміряно при viewport 1280px:

| Контейнер      | `vw`-заголовок | `cqi`-заголовок               |
| -------------- | -------------- | ----------------------------- |
| Wide (794px)   | 40px           | 40px (досягнуто max)          |
| Narrow (256px) | 40px           | 23.36px = 0.5rem + 6 × 2.56px |

## Challenge 7. Fluid Typography — `07-fluid-typography.html`

```css
.hero h1 {
  font-size: clamp(2rem, 1.41rem + 2.61vw, 3.5rem);
} /* 32 → 56px */
.hero-text {
  font-size: clamp(1rem, 0.9rem + 0.43vw, 1.25rem);
} /* 16 → 20px */
```

Як підібрано: пряма лінія через точки «32px на 360px» і «56px на 1280px».
Нахил = (56 − 32) / (1280 − 360) = 0.0261 → **2.61vw**; зсув = 32 − 0.0261 × 360 ≈ 22.6px =
**1.41rem**. Для тексту так само: 16 → 20px.

### Виміряні computed-значення

| Viewport | h1 до (`@media`) | h1 після (`clamp`) | text до | text після |
| -------- | ---------------- | ------------------ | ------- | ---------- |
| 360px    | 32px             | 32px               | 16px    | 16px       |
| 768px    | 44px             | 42.6px             | 18px    | 17.7px     |
| 1280px   | 56px             | 55.97px            | 20px    | 19.9px     |

Розміри майже ті самі, але «після» змінюється **плавно** — немає стрибка +12px на 768px і
1200px. Замість 2 media queries × 2 властивості — 2 рядки. Межі у `rem` + `rem`-складова в
preferred → текст реагує і на налаштування розміру шрифту в браузері.

## Challenge 8. Debug the Layout — `08-debug-broken.html` → `08-debug-fixed.html`

### Як шукали (DevTools)

1. Device Toolbar → 360px: з'явився горизонтальний scroll.
2. Elements → навести на `.page` / `.main` — підсвітка виходить за край вікна.
3. Computed → `width`: `.page` = 1200px, `.main` = 1000px.
4. Grid overlay на `.page`: колонки `300px 900px`, а `.main` (1000px) **ширший за свою
   колонку** (900px) → вилазить навіть на desktop.
5. Flex overlay на `.cards`: картки мають 307px, а не 350px — `flex-shrink: 1` їх стиснув. Тобто
   картки вилазять **разом із занадто широким батьком**, а не самі по собі.
6. Виміряно `scrollWidth` документа: **1300px на 360px і 1300px навіть на 1280px**.

### Таблиця

| Проблема                | Причина                                                                                                                       | CSS-властивість                                      | Виправлення                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Horizontal overflow     | Сторінка має жорстку ширину 1200px, а main — 1000px у колонці 900px                                                           | `.page { width: 1200px }`, `.main { width: 1000px }` | `.page { max-inline-size: 1200px; margin-inline: auto }`; у `.main` `width` прибрано — grid-item сам займає колонку |
| Sidebar займає забагато | Фіксовані 300px: на 360px для main лишається 60px                                                                             | `grid-template-columns: 300px 1fr`                   | Мобільний — `minmax(0, 1fr)`; з 48rem — `minmax(12rem, 1fr) minmax(0, 3fr)`                                         |
| Heading overflow        | `nowrap` забороняє переносити рядок; текст 64px займає 861px у коробці 328px (перевірено окремо, з уже виправленими ширинами) | `white-space: nowrap`, `font-size: 64px`             | `nowrap` прибрано; `font-size: clamp(2rem, 1rem + 4vw, 4rem)`                                                       |
| Card overflow           | Картки в один ряд без переносу + жорстка ширина 350px                                                                         | `.cards` без `flex-wrap`, `.card { width: 350px }`   | `flex-wrap: wrap`; `.card { flex: 1 1 14rem }`                                                                      |

Результат: `scrollWidth` = ширині вікна на 360px і на 1280px.

**Чому не `overflow-x: hidden`:** воно лише **ховає** симптом. Елементи все одно ширші за
екран — частина заголовка і карток була б просто обрізана й недоступна. Причина (фіксовані
ширини і `nowrap`) лишилася б.

## Challenge 10. Final Responsive Component — `10-feature-section.html`

| Вимога                       | Де використано                                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| CSS Grid                     | `.feature-section` (head + сітка), `.features`                                                                                   |
| Flexbox                      | `.feature__inner` (колонка, посилання притиснуте донизу через `margin-block-start: auto`), `.feature__head` (іконка + заголовок) |
| `auto-fit + minmax()`        | `.features`: 3 колонки на desktop, 1 на mobile (виміряно на 360px)                                                               |
| `clamp()`                    | заголовок секції, опис, відступи секції                                                                                          |
| Container Query              | `@container feature (width > 24rem)` — іконка стає ліворуч від заголовка                                                         |
| Іменований контейнер (дод.)  | `container: feature / inline-size`                                                                                               |
| Container query units (дод.) | заголовок картки `clamp(1.1rem, 0.8rem + 3cqi, 1.5rem)`                                                                          |
| Media queries                | **жодної**                                                                                                                       |

Цікавий момент — виміряна ширина картки і стан `.feature__head`:

| Viewport | Колонок | Ширина картки | Іконка    |
| -------- | ------- | ------------- | --------- |
| 360px    | 1       | 273px         | зверху    |
| 480px    | 1       | 386px         | **поруч** |
| 600px    | 1       | 499px         | **поруч** |
| 900px    | 2       | 381px         | зверху    |
| 1280px   | 3       | 322px         | зверху    |

Картка на 600px **ширша**, ніж на 1280px (одна колонка проти трьох). Через `@media` («якщо
екран ширший за X») цю поведінку не описати — вона не монотонна відносно viewport. З
`@container` логіка проста: «у картці є місце — став іконку поруч».
